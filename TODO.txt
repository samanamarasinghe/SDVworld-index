3. CURATED BUT NOT FULLY VERIFIED
--------------------------------------------------------------------------------

    183  confidence: medium  (136 papers, 17 repos, 16 preprints)
     15  confidence: low     (9 papers, 4 repos)

  In the papers lane, `medium` almost always means the publisher would not
  serve the full text to an automated fetch, not that the curator was careless.
  This is the single highest-leverage fix in the project: adding a PDF text
  extractor to the toolchain would move roughly a third of every future papers
  batch from medium to high. There is no pdftotext, fitz, pdfminer or PyPDF2 in
  the default environment; pypdf installs with `pip install --break-system-packages`.

    135  entries carry a `needs` string. Roughly: 23 awaiting a ruling
         (section 1), 11 duplicate questions, 101 verification tasks --
         a full text that would not fetch, a repository that would not clone,
         a classification resting on a file path rather than a read of the code.

     32  scholarly entries have no second source, so the url-vs-DOI
         cross-check in validate.py cannot corroborate their pointer.
      1  code entry is not hosted on GitHub and has no pool row to check.

  Known duplicate questions, both needing a decision then a correction shard:
    - repo-tabularfm-org vs repo-tabularfm: identical titles, org fork vs
      personal account, both vendored_source 4. Test: more commits plus more
      contributors wins; set duplicate_of on the loser.
    - paper-subpopulation-synthetic-ehr-2023 is the arXiv PREPRINT and it is
      the version that survived, while the published JAMIA Open version
      (10.1093/jamiaopen/ooaf091) was never added. This breaks the standing
      rule that the published version is the version of record. The fix is to
      add the JAMIA version and retire the arXiv entry.
    - paper-fingan-crm-banking-2022 (arXiv 2201.11486) has a published twin,
      Neural Computing and Applications 35:6015-6028
      (10.1007/s00521-022-07968-x). Same rule applies. The published PDF has
      been read: its table 9 says LGBM where the preprint entry's evidence says
      xgboost, so fix that line on merge.

    python3 -c "
    import json,re
    idx=json.load(open('data/sdv-index.json'))
    norm=lambda t: re.sub(r'[^a-z0-9]+',' ',(t or '').lower()).strip()

5. SITE AND CODE
--------------------------------------------------------------------------------

  Bugs, smallest first:

  [ ] data/tail/openalex-citations.json stores 14 works twice. Every consumer
      dedupes on read (curate/arxiv_lane.py is the reference implementation);
      the stored file is still wrong. Fixing it at rest is a small script
      nobody has written.

  [ ] harvest/affiliation_normalizations.py maps "stanford university" and
      "stanford cs" to the university's full legal name, which was corrected
      out of the index in shard 107. Regenerating the alias layer would
      reintroduce it. Two occurrences; the file carries CJK, accents and emoji,
      so edit it in place rather than round-tripping it through a tool.

  [ ] One unmerged remote branch, agent/add-canonical-authors-affiliations,
      whose work reached main by another route. Deleting a branch needs the
      owner's say-so.

  Worth building:

  [ ] Nothing in the repo checks what the PAGE shows. validate.py checks data.
      A filter regression that hid 668 entries shipped and was caught by a
      human reading the header count. The fix is a stub-DOM harness: about 40
      lines of fake document/fetch in node, vm.runInThisContext on the real
      assets/js/sdv-index.js, then read pubs-count.textContent and drive the
      sliders and buttons. Compare counts at importance 0 / popularity 0,
      at 4 / 0, and at the defaults. docs/site.md records the reference counts
      and the two stubs that are easy to miss.

  [ ] A machine-readable retraction flag. One indexed work is retracted
      (10.52783/jes.2913, shard 100); the retraction is stated in its summary
      and nowhere a program can see it. Proposed: `retracted: true`.
      validate.py has no key allowlist, so an extra key passes.

6. CLOSED -- DO NOT RESTART THESE
--------------------------------------------------------------------------------

  * The repository tail. About 1400 pooled repositories, almost all with zero
    stars, will not be read. They stay in data/tail/github-repos.json at low
    importance and are hidden by any importance floor above 0. Indexing them
    unread would put summary clauses in the index that came from no source,
    which is the one rule everything else here rests on.

  * The self-archive hunt on the login-required works. Confirmed empty five
    ways: Unpaywall, Semantic Scholar openAccessPdf, OpenAlex locations,
    OpenAlex fuzzy title search for sibling preprints, and the arXiv API.
    These are regional engineering journals whose author communities do not
    self-archive. If a NEW closed set appears, run Unpaywall and OpenAlex
    first, then web search the residual -- in that order.

  * Two records in the tail look uncurated but were deliberately removed as
    preprint duplicates: 10.48550/arxiv.2210.13423 and
    10.48550/arxiv.2211.07369. Never re-add them.

  * The Google Scholar lane, unless a SERPAPI_KEY turns up. Scholar publishes
    no API and its terms forbid automated querying; if it serves a CAPTCHA,
    stop rather than working around it.
